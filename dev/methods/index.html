Method comparison

The initial proposal must cover the target. Adaptation can improve it but cannot recover regions that the run never visits.

Choosing a method

The proposal and available model operations determine a useful starting point.

SituationStarting pointMain consideration
A fixed proposal already covers the target wellPlain ISAlso useful for production after an independent pilot
Several fixed proposals cover different regionsStatic MISFull-mixture weighting evaluates every active density
One proposal needs moment fittingAMIS or N-PMCAMIS recycles history; N-PMC fits each round using clipped weights
Population locations need to move, but widths are already suitableDM-PMC or APISNeither tunes covariance; resampling and local mean fitting behave differently
MCMC moves can locate useful population centresLAISUpper moves and tuning add work beyond the returned samples
Population widths also need fittingCAISEach proposal needs enough local samples for a viable fit
Reliable target gradients are availableFirstOrderGRAMISGradient and backtracking costs must be worthwhile

AMIS updates earlier denominators, which adds proposal-density work and history storage. N-PMC leaves earlier weights unchanged. A single fitted proposal may still miss separated modes. The DM-PMC example checks an asymmetric two-mode target.

Use an independent fixed-proposal production run when you want the usual independent-draw Monte Carlo error analysis. No method dominates for every target, budget, and estimand.

GR-PMC and LR-PMC use DeterministicMixturePMC with different resampling policies. FirstOrderGRAMIS is a first-order hybrid, not the Hessian-based GRAMIS paper algorithm.

Preparation and execution

prepared = prepare_sampler(rng, logtarget, p, algorithm)samples = importance_sample!(prepared)

For a single run, importance_sample(rng, logtarget, p, algorithm) combines both steps. Omit p for a context-free target.

Adaptive algorithms require rounds and round_size. An integer repeats the total round size. A vector gives one total count per round. All rounds contribute to the returned result.

Only AMIS retrospectively changes earlier weights. The other adaptive methods retain each sample's original round weight.

Allocation requirements

MethodPer-round allocation requirement
AMIS, N-PMCOne proposal with a positive round size and a viable moment fit
DM-PMCAt least one draw for each active proposal
APISEqual positive masses, divisible round size, at least two draws per proposal
LAISEqual positive masses, divisible round size, at least one draw per proposal
HAISEqual positive masses, divisible round size, at least one draw per proposal
CAISEqual positive masses, divisible round size, at least d + 2 draws per proposal
FirstOrderGRAMISAt least two distinct initial means, equal positive masses, at least d + 2 draws per proposal

These are admissibility conditions, not recommended statistical budgets. Covariance fitting and tail coverage often need substantially more samples.

Budgets and checks

For M equally allocated population proposals, each generates round_size / M draws. Proposal-local fits use only their own draws. A larger population leaves fewer draws per local fit at a fixed round size. Choose initial widths that cover each region; more rounds do not tune fixed widths.

The logistic tutorial uses 8,000 pilot draws and 20,000 independent production draws. Its separate budgets are illustrative, not precision guarantees. Time the pilot, inspect its diagnostics, then check the production estimate across independent streams and larger budgets. A high weight ESS does not establish coverage of missed modes or tails. Count pilot work, proposal-density evaluations, and LAIS upper moves in total cost.

Proposal support

All population methods accept native Gaussian or Student-t proposals. DM-PMC and APIS also accept independent Gamma and Laplace populations. LAIS also accepts independent Laplace lower proposals. AMIS and N-PMC support independent Gamma and Laplace moment fits. Method compatibility lists proposal families; Proposals explains layouts and the Student-t covariance convention. Devices lists backend support.
